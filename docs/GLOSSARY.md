- Кредитный риск (credit risk) - Риск, что заёмщик не вернёт деньги

- Дефолт (default) - Неспособность платить. Обычно это просрочка 90+ дней; в Home Credit проблемы с первыми платежами

- DPD (days past due) - Сколько дней просрочен платёж. «90+» значит просрочка больше 90 дней

- PD (probability of default)	Вероятность дефолта клиента. Её оценивает наша модель

- LGD (loss given default)	Доля долга, которую теряем при дефолте. LGD = 1 − recovery rate

- Recovery rate	Доля долга, которую удаётся взыскать после дефолта

- EAD (exposure at default)	Сумма долга на момент дефолта
 
- EL (expected loss)	Ожидаемые потери: PD × LGD × EAD

- Стоимость фондирования (cost of funds)	Сколько банк сам платит за привлечённые деньги

- Кредитный конвейер (credit pipeline)	Путь заявки: антифрод → стоп-факторы → скоринг → решение → мониторинг → взыскание

- Заявочный скоринг (application scoring)	Оценка риска на момент подачи заявки. Наш случай

- Поведенческий скоринг (behavioral scoring)	Оценка риска уже существующих клиентов по их поведению

- БКИ (credit bureau)	Бюро кредитных историй: данные о кредитах клиента в других банках

- Скоркарта (scorecard)	Модель в виде таблицы баллов: значение признака даёт столько-то баллов, сумма баллов определяет решение

- WoE и IV	Способ преобразования признаков и мера их силы. 

- ROC AUC	Вероятность, что модель поставит случайного «плохого» клиента выше случайного «хорошего». 0.5 означает угадывание, 1.0 идеал

- Gini	2 × AUC − 1. То же качество ранжирования, банковская шкала

- Калибровка (calibration)	Совпадают ли предсказанные вероятности с фактической частотой. Если модель говорит «10%», дефолтов должно быть около 10%

- Порог отсечения (cut-off)	Граница скора: выше одобряем, ниже отказываем

- Approval rate	Доля одобренных заявок

- Bad rate	Доля дефолтов среди одобренных

- Overlay	Наша модель как дополнительный фильтр поверх существующей политики банка

- Смещение отбора / reject inference (selection bias)	Таргет известен только у одобренных; про отказников мы не знаем, вернули бы они или нет

- Дисбаланс классов (class imbalance)	Дефолтов около 8%, поэтому accuracy бесполезна

- Утечка данных (data leakage)	Использование в модели информации, недоступной на момент решения

- Out-of-time валидация	Проверка модели на более позднем периоде, чем обучение. 

- Анализ чувствительности (sensitivity analysis)	Как меняется вывод при изменении допущений (LGD, ставки)

- Зерно таблицы (grain)	Что означает одна строка таблицы: клиент, кредит или месяц истории

- ADR (architecture decision record)	Журнал решений с альтернативами. У нас это DECISIONS.md

- БКИ - Бюро кредитных историй


| Термин | Простыми словами |
|---|---|
| Витрина данных (data mart) | Подготовленная под задачу таблица: одна строка на клиента, все признаки и таргет |
| Профилирование данных (data profiling) | Проверка, что данные устроены так, как мы думаем: ключи, пропуски, диапазоны, аномалии |
| Base rate | Базовая доля дефолтов во всей выборке (у нас 8.07%), точка отсчёта для сравнений |
| Покрытие (coverage) | Доля клиентов, у которых есть записи в источнике |
| Тонкое досье (thin file) | Клиент без кредитной истории в бюро |
| Заглушка (sentinel value) | Служебное значение вместо пропуска, например 365243 в `DAYS_*` |
| Размножение строк (fan-out) | Джойн двух связей 1:M от одного родителя даёт произведение строк и искажает суммы |
| Сверка с источником (reconciliation) | Одна величина, посчитанная двумя независимыми путями, должна совпасть |
| Производная таблица (derived table) | Подзапрос в `FROM`, с которым работают как с таблицей |
| CTE (common table expression) | Именованный подзапрос в блоке `WITH`, читается сверху вниз |
| Полусоединение (semi-join) | Фильтр по наличию в другой таблице (`IN`, `EXISTS`) без добавления её столбцов |
| `FILTER (WHERE ...)` | Условный агрегат в DuckDB/PostgreSQL, короткая запись `SUM(CASE WHEN ...)` |
| `NULLIF(a, b)` | NULL, если a = b, иначе a. Защита знаменателя и замена заглушек |
| `COALESCE(a, b)` | Первый не-NULL аргумент. Превращает NULL в 0, где ноль осмыслен |
| Recovery rate | Доля долга, взысканная после дефолта. LGD = 1 − recovery rate |
| ПДН (показатель долговой нагрузки) | Доля дохода на платежи по всем кредитам. ЦБ РФ требует считать его при выдаче |
| Прокси (proxy) | Признак, который не причина сам по себе, а коррелирует с причиной |
| Косвенная дискриминация (proxy discrimination) | Модель без защищённого признака восстанавливает его через другие признаки |
| Аудит справедливости (fairness audit) | Сравнение решений модели между группами (например, доля одобрения по полу) |
| CLAUDE.md | Файл инструкций, который Claude Code читает в начале каждой сессии |
| Навык (skill) | Папка с инструкциями для Claude Code, подгружается, когда задача ей соответствует |
| Хук (hook) | Shell-команда, которую Claude Code автоматически выполняет на событие |
| Кредитный голод (credit hunger) | Много заявок за короткий срок, часто после отказов. Признак финансового стресса |
| SK_DPD_DEF (DPD with tolerance) | Просрочка без учёта мелких долгов. Копеечная недоплата не считается риском |
| Статус Demand | Банк потребовал досрочно вернуть весь долг. Обычно после серьёзной просрочки, перед взысканием |
| Утилизация лимита (credit utilization) | Баланс карты / лимит. Выше 1 означает траты сверх лимита |
| `arg_max(x, y)` | Значение x в строке, где y максимален (DuckDB). Аналог в PostgreSQL: `ROW_NUMBER()` + фильтр |
| `GREATEST(a, b)` | Наибольший из аргументов. `GREATEST(x, 0)` обрезает отрицательные значения до нуля |
| Общая доля (pooled share) | Сумма числителей / сумма знаменателей. В отличие от среднего долей, длинные истории весят больше |
| Стратифицированное разбиение (stratified split) | Разбиение, при котором доля дефолтов одинакова в train, valid и test |
| Train / validation / test | Обучение модели / подбор настроек и порога / одна финальная честная оценка |
| fit / transform | Параметры преобразования (WoE, бины, медианы) учатся только на train (fit) и применяются к остальным (transform) |
| Parquet | Колоночный формат файла: компактный, хранит типы, быстро читается pandas и DuckDB |
